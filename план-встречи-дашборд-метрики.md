ПЛАН СЛЕДУЮЩЕЙ ВСТРЕЧИ — СОЗДАНИЕ ВИЗУАЛЬНОГО ДАШБОРДА
(твёрдые + мягкие метрики)
=============================================================

ЦЕЛЬ ВСТРЕЧИ
--------------
Перейти от идеи «нужен дашборд» к первому рабочему макету: выбрать 1-2
пилотных проекта, определить твёрдые и мягкие метрики, источники данных,
визуальный формат и зафиксировать еженедельный ритм. Не пытаться сразу
покрыть все проекты — пилот, затем расширение.

Если до встречи получены ответы на «вопросы-сергею-о-целях-и-метриках.md» —
шаги 1-3 проходим быстрее, как сверку, а не как первичный разбор.


ШАГ 1. СВЕРКА ПРИОРИТЕТОВ (10-15 минут)
-------------------------------------------
ДЕЛАЕМ: проходим по списку всех проектов, для каждого — статус (движется /
стоит) и главный «пожар» сейчас. Выбираем 1-2 пилотных проекта для дашборда.

НА ВЫХОДЕ: список 1-2 пилотных проектов + по одному «пожару №1» для каждого.


ШАГ 2. ТВЁРДЫЕ МЕТРИКИ ПО ПИЛОТНЫМ ПРОЕКТАМ (15-20 минут)
-------------------------------------------------------------
ДЕЛАЕМ: для каждого пилотного проекта определяем 3-5 показателей:
   - статус / % выполнения
   - дедлайн / следующая контрольная точка
   - ответственный исполнитель (кто реально делает, не кто «назначен»)
   - «светофор» (зелёный / жёлтый / красный)
Для каждого показателя сразу фиксируем источник данных — кто и как сообщает.

НА ВЫХОДЕ: таблица «проект → метрика → источник данных → частота обновления».


ШАГ 3. МЯГКИЕ МЕТРИКИ (15-20 минут)
---------------------------------------
ДЕЛАЕМ: переносим в дашборд эмоционально-ценностный слой:
   - шкала счастья / энергии (1-10) — ежедневно или еженедельно
   - «покой в душе» — операционализируем (например: количество конфликтов
     за неделю, часы сна, был ли хотя бы 1 момент потока)
   - «нега в теле» по утрам — простой маркер да/нет
   - количество «пожаров», потушенных за день — как индикатор перегрузки

НА ВЫХОДЕ: 3-5 мягких метрик с понятным способом самооценки (без сложных
шкал — то, что реально заполнить за минуту голосом вечером).


ШАГ 4. КАРТА «УЗКИХ ГОРЛЫШЕК» ПО ПИЛОТНЫМ ПРОЕКТАМ (15 минут)
-------------------------------------------------------------
ДЕЛАЕМ: по каждому пилотному проекту называем текущее «узкое горлышко» —
по формуле «где внимание, там энергия». Привязываем каждое горлышко к роли
«мама/папа»: где сейчас Сергей «мама», и можно ли сразу обозначить шаг к
«папе» (что и кому делегировать).

НА ВЫХОДЕ: 1-2 узких горлышка на проект + первый шаг по каждому к роли
«папа».


ШАГ 5. ИСТОЧНИКИ ДАННЫХ И ФОРМАТ СБОРА (10-15 минут)
---------------------------------------------------------
ДЕЛАЕМ: решаем, как данные попадают в дашборд:
   - голосовые сообщения в Telegram (Wispr Flow / Aqua Voice → расшифровка)
   - форма (Яндекс/Google Формы) для сотрудников по их метрикам
   - кто заполняет, как часто — без перегрузки (минимум полей)

НА ВЫХОДЕ: для каждой метрики из шагов 2-3 — конкретный канал ввода данных.


ШАГ 6. ВИЗУАЛЬНЫЙ МАКЕТ ДАШБОРДА (15-20 минут)
---------------------------------------------------
ДЕЛАЕМ: набрасываем структуру экрана (на бумаге/доске, без кода):
   - верх — мягкие метрики (счастье / энергия / покой в душе) за неделю
   - середина — карта пилотных проектов: статус-светофор + текущее узкое
     горлышко по каждому
   - низ — приоритеты недели / следующий главный шаг
Выбираем инструмент для первой версии: Notion, Airtable, Google Sheets, или
кастомный экран на базе Claude Code (быстрее всего для прототипа).

НА ВЫХОДЕ: эскиз макета + выбранный инструмент для прототипа.


ШАГ 7. ЕЖЕНЕДЕЛЬНЫЙ РИТМ (5-10 минут)
-------------------------------------------
ДЕЛАЕМ: фиксируем постоянный день/время еженедельной сверки. Договариваемся
о формате: что Сергей готовит ДО встречи (голосовая выгрузка по пилотным
проектам и мягким метрикам), что разбираем НА встрече (пульс + узкое
горлышко + следующий главный шаг).

НА ВЫХОДЕ: фиксированный слот в календаре + шаблон «что готовить перед
встречей».


ШАГ 8. ДОГОВОРЁННОСТЬ О ПИЛОТНОМ ПЕРИОДЕ (5 минут)
-------------------------------------------------------
ДЕЛАЕМ: договариваемся о пилоте на 2 недели с 1-2 проектами и базовым
набором метрик. После пилота — ревизия: что сработало, что упростить, как
расширять на остальные проекты.

НА ВЫХОДЕ: дата ревизии пилота + критерий «пилот сработал», если он:
   - реально занимает не больше времени, чем договорились (шаг 5 в вопросах
     Сергею — 15-20 минут в день)
   - даёт Сергею ответ на вопрос «как дела у проекта» без необходимости
     лезть в детали самому


ИТОГ ВСТРЕЧИ
--------------
К концу встречи должны быть зафиксированы: 1-2 пилотных проекта, твёрдые и
мягкие метрики по ним, источники данных, эскиз макета, еженедельный ритм и
дата ревизии пилота. Общая длительность — примерно 90-100 минут с запасом.
